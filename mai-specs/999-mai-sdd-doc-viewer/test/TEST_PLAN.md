# 业务测试计划：999-mai-sdd-doc-viewer

> Feature：999-mai-sdd-doc-viewer | 有效需求与验收来源：[PRD.md](../spec/PRD.md)（AC-01 至 AC-11） | 技术方案：[TECH_DESIGN.md](../design/TECH_DESIGN.md) | 设计评审：[design_review.md](../review/design_review.md)（复评通过） | Profile：standard | 状态：仅规划，未执行

[返回需求简报](../BRIEF.md)

本计划从用户与作业评审者视角定义如何验证只读浏览、空态与失败恢复、无副作用以及交付完整性。当前插件源码与自动化测试尚未实现，因此本计划只给出待验用例、已有参考入口和执行条件，不记录执行结果，也不把设计文档或静态路径当作业务通过证据。

## 范围与依据

本次范围是 PRD 的 AC-01 至 AC-11：专用入口与面板、按 Feature 发现与排序、只读 Markdown 预览、同名文档身份、三类空态、失败重试、重新读取外部变更、无模型/命令/凭据副作用、键盘与窄屏及中英文、插件清单与作业证据、既有 Sidebar 回归。范围外包括：SDD 命令或 LLM 能力、全文搜索、自定义排序、非 Markdown 渲染、Mermaid 扩展与自动 Git 提交，均按 PRD 第 7 节排除。

预期结果一律取自 PRD 的 AC、BR 与 COPY 文案，以及设计中已确认的状态语义（加载、空态、失败、删除选择）。实现现状只用于识别差异，不用于下调验收条件。

硬约束作为每个用例的横切断言：插件只读；不执行 `mai`/SDD/Git 或其他子进程；不发起 LLM 请求、不要求或读取 API Key；不写规格文件；不把浏览内容注入模型请求、提示词、工具或会话事件。

## 待验业务用例

### TC-01：无 API Key 启动并进入面板

- 关联需求：AC-01、FR-01、FR-07、BR-04、BR-06、NFR-01
- 前提与数据：`plugins/mai-sdd-doc-viewer/` 下 `package.json`、`cordis.patch.yml`、`client.js`、`icon.svg`、`README.zh.md`、`README.md` 六个必备文件齐全；运行环境未设置任何 LLM API Key；DSH Web 组合已启用该插件；工作区含 `mai-specs`。
- 操作步骤：
  1. 以无 Key 环境启动 DSH Web，记录启动命令与环境变量检查结果。
  2. 打开右侧 Sidebar 引导入口，用键盘定位并激活“SDD 文档”。
  3. 观察面板、现有入口，以及启动与浏览期间的命令、网络和模型观察记录。
- 预期结果：面板显示 COPY-01 标题与 COPY-02“重新读取”；出现 COPY-03 或文档树；没有 API Key 引导或配置要求；没有 SDD 命令、其他子进程或 LLM 请求；文件页、Markdown 预览与插件管理入口仍可用。
- 验证方式与证据：静态文件清单；无 Key 启动日志；键盘操作截图；进程与请求观察记录。可作为 T6 自动化用例的无 Key 启动前置。
- 清理：结束 Web 进程，恢复被改动的临时环境变量。

### TC-07：重新读取外部变更

- 前提与数据：面板已显示一个 Feature 与当前文档；准备外部编辑的三种变更：修改当前文档正文、新增另一篇 `.md`、删除当前文档；记录插件目录与规格目录的写操作观察方式。
- 操作步骤：
